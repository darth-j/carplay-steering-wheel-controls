# Adapter contract

The core operates on logical buttons and primitive state values. It does not ship a vendor adapter, SDK, firmware class, installer or network client.

## Logical input

- Buttons: `STAR`, `ROLLER`, `VOICE`, `NAVIGATION_VOICE`.
- Events: `PRESS`, `RELEASE`, `LONG_PRESS`, `DOUBLE_PRESS`.
- `steeringWheelSource` must come from a verified input-source mapping. Do not infer it from the button number alone; another control surface may reuse that number.
- Map hardware IDs locally. No device-specific IDs, connected-screen model IDs, diagnostic addresses or firmware versions are included here.
- Preserve native behavior when `onKey` returns false. Do not call both custom and native paths for consumed events.
- Update connection and page state independently. Call `updateConnection(false, false)` at a real disconnect. Do not substitute “application started” for “phone connected”.
- Feed only a normalized connected/page boolean to the library. Any interpretation of vendor state models belongs in the adapter.

## Media port

`mediaButton` represents a complete press/release transport action. The reference protocol values are:

| Value | Meaning |
|---|---|
| 9 | Next track |
| 10 | Previous track |
| 13 | Answer |
| 18 | Pause |
| 19 | Play |

Verify these against the target interface before use. Logical engine button values are separate from these transport values.

`PlaybackPolicy` additionally recognizes transport value 15 as play/pause. It does not send this toggle for the roller: explicit pause/play is selected from reported playback state.

Playback values are normalized as 1=playing, 2=paused, 3/4=seeking. Invalid callbacks must be passed with `valid=false`. Unknown state must not be treated as proof that the phone was paused before connection.

Apply `playbackPolicy().new ButtonGate()` at the outbound command boundary if the adapter can also observe native automatic commands. Reset the gate at connection boundaries. Checking only commands generated by this library will not intercept commands generated elsewhere.

Manual playback from the phone or CarPlay UI should reach the normal playback callback. If the adapter has other explicit transport controls, call `userTransportRequested()` for those verified actions, rather than disabling protection for every generic navigation key.

`showCarPlay` must request the screen only. Do not use “show page” as a reason to send Play or to force a media-focus change. `requestMediaFocus` is invoked for explicit media actions, never for the pause branch or the Siri sequence.

## Siri

Implement all three methods in the same target command-queue domain:

1. `siriPressed()`
2. `siriLongDetected()`
3. `siriReleasedAfterLongPress()`

The final release is mandatory even when the long-detection action fails. Do not replace this with an incomplete diagnostic “long press” helper that omits release. Do not log microphone data or voice content.

## Phone state and rejection

The sample normalization is status 0=disconnected, 1=active, 2=holding, 3=connecting, direction 0=incoming, 1=outgoing. These values are **adapter contracts**, not universal constants. Verify the source interface and convert its values before calling the library.

The status stream must actually be subscribed at the source. Adding an empty callback implementation alone does not establish a subscription. Only status and direction are needed; strip caller identity before handing data to this library.

`endCallKey(false)` is physical press, `endCallKey(true)` is release. Do not invert these booleans. On incoming calls, release is scheduled to maintain the configured rejection hold. On active calls, release follows the physical event without the extra rejection delay.

The default 1500 ms comes from a reference integration, not a universal phone requirement. Keep it configurable. Multi-call waiting, devices that interpret the hook differently and provider errors require adapter-level tests before deployment.

The port must report errors honestly. Do not silently fall back to an unverified call-control action that can answer an incoming call instead of rejecting it.

## Scheduling, state and failure handling

- `Clock` should be monotonic and `Scheduler.after` nonblocking.
- Schedule once and run the supplied task once. Do not sleep inside a device input callback.
- Calls into a firmware service may enqueue work, but must not synchronously wait for a second thread that needs to re-enter the controls object.
- When disabling input or disconnecting, the engine clears captures and releases an outstanding phone key. Old scheduled tasks are generation-checked.
- An input adapter should apply its original power/standby/lockout restrictions via `setInputAllowed`. This library cannot infer them.
- Deployment, compatibility checks, backups and recovery are outside the scope of this repository.

## Hardware validation

The tests prove the portable engine's behavior with fake ports. They do not prove the vendor adapter, proprietary service ABI, phone app, embedded JVM or physical input mapping.

Before enabling an adapter persistently, verify native passthrough, play/pause without unintended focus changes, Siri execution, incoming/active call transitions, rejection, disconnect cleanup and recovery. Keep the validation data synthetic or anonymized if contributing a test.
